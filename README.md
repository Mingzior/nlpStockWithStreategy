# StockLens AI｜自然语言智能选股与策略解释器

> 题目 02 · 24 小时产品开发挑战 · 当前阶段：交互产品建设中

**代码仓库：** https://github.com/Mingzior/nlpStockWithStreategy

## 产品需求文档（PRD）

### 一、背景及用户痛点
普通投资者经常用“经营改善、估值合理、走势稳定”等模糊措辞表达意图，却难以转换为明确的财务、估值与交易指标。传统筛选器要求用户预先懂得每个指标，黑箱 AI 直接推荐股票又难以验证。产品目标不是代替投资决策，而是让选股意图变成**可审查、可修改、可执行、可追溯**的条件。

### 二、用户及核心场景
- 初学者：输入自然语言，获取具体指标建议及不确定性提示。
- 有经验的研究者：修改阈值，检查命中/排除原因与条件敏感性。
- 策略研究者：保存策略、对比候选股票，了解数据缺失和统计口径。

### 三、设计目标与指标
1. 自然语言到结构化条件的可解释转换（每项包括字段、运算符、阈值、单位及转换原因）。
2. 可逐项编辑条件，检测相互矛盾的上下限。
3. 筛选由确定性代码执行；每只股票呈现逐项通过/失败/缺失。
4. 对每个结果标注源数据提供者、日期、口径；缺失不视为通过。
5. 记录策略保存、比较及筛选变化。

### 四、架构与职责边界
- **AI / NLP 层：** 提议结构化筛选条件及澄清问题；不计算股票事实，不承诺收益。未配置模型时采用明确标识的规则式解析器。
- **筛选引擎：** 使用确定性比较运算、缺失传播及冲突检测；不使用生成式模型判定命中。
- **金融数据层：** 扶摇 API / iFinD MCP 优先，必须在服务器端保管凭据，核查接口许可、权限与字段映射。连接不可用时使用明确标识的**合成演示数据**，不得声称是真实行情。
- **前端：** 策略编辑、数据口径、结果及排除原因、对比和保存。

### 五、核心交互
1. 输入中文意图，如“盈利增长、估值不太贵、波动小”。
2. 查看系统映射出的筛选条件，可编辑阈值/操作符并移除条件。
3. 识别同一指标上的上下界冲突，并提示修改；存在冲突时阻止正常执行。
4. 点击执行，得到入选、排除和缺失结果；每项回溯原始字段和数据日期。
5. 选择股票比较、调整条件重新执行、保存本地策略。

### 六、功能设计与边界
- 高优先级：NLP 转条件、澄清、可编辑条件、冲突识别、确定性筛选、透明结果及数据来源。
- 次优先级：策略本地保存、候选比较、敏感性变化提示。
- 未完成不得冒充已完成：真实数据 API 对接、历史回测、服务端监控提醒及实盘交易。
- 异常：接口超时、字段为空、时点不一致、负值与单位异常需要明确显示失败或不确定，不得静默补全。
- 合规：不输出买卖建议、确定性涨跌预测、收益保证；不上传密钥、隐私或未授权金融数据。

### 七、验收口径
可在线访问并实际完成输入→结构化→编辑→冲突检测→筛选→解释→保存/比较；至少验证正常链路、缺失值、冲突阈值、空结果、错误输入和数据不可用。没有真实数据的演示只算交互功能验证，**不算真实行情筛选验收**。

## 技术与启动
计划使用 TypeScript、React、Vite、Tailwind；在根目录运行 `npm install && npm run dev`（代码发布后生效）。真实金融接口凭据只允许配置在服务器端安全环境变量中，不允许使用前端 `VITE_` 变量暴露密钥。
